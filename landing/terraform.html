Terraform

Every resource block, reviewed before apply

Point GreenSecOps at any folder in your repo — root modules, per-environment directories, whatever your layout — and every .tf / .tf.json file is graded across three categories.

Security
  • Public S3 bucket ACLs exposing data to the internet
  • Security groups with unrestricted 0.0.0.0/0 ingress
  • Unencrypted RDS instances
  • Unencrypted EBS volumes
  • Hardcoded credentials in Terraform source
Reliability
  • S3 buckets missing versioning, risking irrecoverable data loss
  • Configuration that undermines durability and recovery
Maintainability
  • Resources missing tags for ownership and cost tracking
  • Variables missing descriptions
How It Works

No plan files, no apply required

GreenSecOps analyses your Terraform source directly — it never needs cloud credentials or a terraform plan to grade your configuration.

1
Choose your Terraform folders

Tell GreenSecOps which directories hold your Terraform. Any layout works — a single root module or dozens of per-environment folders.

2
Graded on every push

Each push parses your .tf files and runs the shared Rego rule catalog, returning per-category grades in seconds — long before anything reaches your cloud.

3
Fix it in a pull request

Review each finding with remediation guidance, generate an AI fix, and open a pull request — so misconfigurations never make it to apply.

AWS Cloud Posture

Grade what's actually running

Terraform tells you what you intend to deploy. Cloud posture tells you what's live — drift, manual changes, and all. Connect an AWS account read-only via sts:AssumeRole — no access keys, ever.

Identity & access
  • Over-permissive IAM policies and wildcard grants
  • Security groups exposing ports to the public internet
  • CloudTrail coverage gaps that blind your audit log
Data & storage
  • Public or unencrypted S3 buckets
  • Unencrypted RDS instances and EBS volumes
  • Missing durability and backup safeguards
Compute & hygiene
  • Lambda functions with risky configuration
  • Untagged, unowned resources across the account
  • Drift between your Terraform and live state
1
Create a read-only role

Add an IAM role that GreenSecOps assumes via sts:AssumeRole. Read-only, scoped, and revocable at any time — no long-lived access keys change hands.

2
Scan on demand or on schedule

GreenSecOps inspects S3, IAM, security groups, RDS, EBS, Lambda, and CloudTrail across your account and grades each finding.

3
Close the loop with Terraform

Trace live findings back to the Terraform that should own them, and fix the source instead of patching the console.
